How it works

Columns

  • [Care] Units: one column for each care setting in the deal (AL, MC, IL, SNF, or a custom setting's initials, using the same abbreviations as the short care names). Settings the deal doesn't have get no column.
  • Long headers wrap onto two lines (Total / Units) so all 8 columns fit on a letter-size page.
  • Total Units: rooms (the old "Apartments").
  • Beds: residents, with shared rooms counted twice.
  • Sensors: the total, with the math below it, e.g. 75 Incl. + 57 Addl. One sensor is included per bed, and the contingency is in the Addl. number.
  • Edge Units: one per room unless a room was set to more.
  • E-Call Pendants or E-Call Pull-Cords, depending on the system. Only shown when E-Call is in the deal.

This round

  • Sensor math, Stacked (recommended): "Incl." and "Addl." sit in two small lines to the right of the total, with no plus sign. The row stays one line tall, and the table keeps 8 columns.
  • Sensor math, Columns: a Sensors group with Incl. | Addl. | Total, like the scope PDF. Easiest to scan and still fits on a letter-size page with E-Call, but rows take more width and the Community column gets less room for long names.
  • Header cards: the totals cards (Sensors, Edge units, E-Call) show above the table by default (Condensed). Expanded opens each card to list every community's count, and Off hides them. Both changes animate.
  • Unlike in the room-type view, turning the cards on doesn't remove the total columns from the table: this table is about the counts, so they stay.
